# Add Kotlin integration-test code action for existing-or-new tests

Add a Kotlin code action on class declarations that opens an existing matching integration test or creates a new one when absent. Prefer 'integration' terminology instead of 'e2e'. Use conservative conventions and only offer the action when an unambiguous integration-test root and naming convention can be determined. This ticket is split out of ka-gjfa.

## Design

Mirror the unit-test code action (ka-26kw) architecture for integration tests:

### Planner: KotlinIntegrationTestPlanner

Create `sidecar/src/main/kotlin/dev/kouros/sidecar/KotlinIntegrationTestPlanner.kt` following the `KotlinUnitTestPlanner` pattern.

**Key constants:**
- `SOURCE_ROOT = "src/main/kotlin"`
- `TEST_ROOTS` — ordered candidates: `src/integrationTest/kotlin`, `src/e2eTest/kotlin`, `src/testIntegration/kotlin`
- `GENERATED_METHOD_NAME = "hurz"` (match unit-test convention)
- Naming: `FooService` → `FooServiceIntegrationTest`

**Planning logic (sealed interface `KotlinIntegrationTestPlan`):**
- `Existing(targetPath, targetUri, targetClassName, selection)` — existing integration test found
- `Create(targetPath, targetUri, targetClassName, initialContents, selection)` — generate new test
- `Unavailable(reason)` — cannot determine integration test root or conventions

**Conservative detection:**
1. Validate source file is under `src/main/kotlin`
2. Scan for integration test root candidates in order; use first that exists on disk
3. If no integration test root exists → `Unavailable("no integration test source root found")`
4. Mirror package path under the chosen integration test root
5. Look for `{ClassName}IntegrationTest.kt`
6. If found → `Existing` with selection on first `@Test` method
7. If not → `Create` with generated skeleton

**Generated skeleton:**
```kotlin
package {mirrored.package}

import org.junit.jupiter.api.Test

class {ClassName}IntegrationTest {

    @Test
    fun hurz() {
        // cursor here
    }
}
```

### Code Action Wiring

**CompilerBridge.kt** — add `addOpenOrCreateIntegrationTestAction()` near line 1909, next to `addOpenOrCreateUnitTestAction()`:
- Reuse `findUnitTestActionClass()` (line 2087) for class detection — rename or extract to `findTestActionClass()` if cleaner
- Call `KotlinIntegrationTestPlanner.plan()` with same inputs
- Build command using existing `AnalyzerCommands.OPEN_TEST_TARGET` / `CREATE_AND_OPEN_TEST_TARGET` — no new commands needed, the transport is identical
- Action title: `"Open or Create Integration Test"`

### Command Execution

No Rust server changes needed. The existing `OPEN_TEST_TARGET` and `CREATE_AND_OPEN_TEST_TARGET` commands in `server/src/server.rs` (lines 480-505) handle file creation and `show_document()` navigation generically. The integration test action just produces different target paths and contents.

## Implementation Steps

### Step 1: Create KotlinIntegrationTestPlanner

Create `sidecar/src/main/kotlin/dev/kouros/sidecar/KotlinIntegrationTestPlanner.kt`:
- Sealed interface `KotlinIntegrationTestPlan` with `Existing`, `Create`, `Unavailable`
- `plan()` function mirroring `KotlinUnitTestPlanner.plan()` but with integration test root detection
- `generateContents()` for the test skeleton
- `findExistingSelection()` for cursor placement in existing tests

### Step 2: Wire into CompilerBridge

Add `addOpenOrCreateIntegrationTestAction()` in `CompilerBridge.kt`:
- Call it from `codeActions()` near line 1909
- Reuse `findUnitTestActionClass()` for class detection
- Call `KotlinIntegrationTestPlanner.plan()` and build command

### Step 3: Add planner unit tests

Create `sidecar/src/test/kotlin/dev/kouros/sidecar/KotlinIntegrationTestPlannerTest.kt`:
- Existing integration test detection with mirrored path
- New integration test creation with JUnit skeleton
- Rejection when source is not under `src/main/kotlin`
- Rejection when no integration test root exists
- Correct test root selection when multiple candidates exist

### Step 4: Add integration tests

Create `sidecar/src/test/kotlin/dev/kouros/sidecar/KotlinIntegrationTestCodeActionIntegrationTest.kt` following `KotlinUnitTestCodeActionIntegrationTest.kt` (267 lines):
- Test: class with existing mirrored integration test returns `OPEN_TEST_TARGET` command
- Test: class without integration test returns `CREATE_AND_OPEN_TEST_TARGET` command
- Test: no integration test root → no action offered
- Test: generated integration test compiles when classpath is available (Gradle fixture)

### Step 5: Add fixture

Create `tests/fixtures/gradle-kotlin-integration-test/` with:
- `src/main/kotlin/` — source class
- `src/integrationTest/kotlin/` — integration test root (with and without existing tests)
- `build.gradle.kts` — JUnit 5 dependency, `integrationTest` source set registration

### Step 6: Verify

```bash
cd sidecar && ./gradlew test
cargo test
```

## Acceptance Criteria

- On a Kotlin class with an existing integration test, invoking the action opens the integration test class.
- On a Kotlin class without a matching integration test, invoking the action creates a new integration test.
- The user-facing naming uses 'integration', not 'e2e'.
- Behavior is conservative when no clear integration test root or naming convention can be determined.
- Add tests covering existing-test navigation and new-test generation for integration tests.
