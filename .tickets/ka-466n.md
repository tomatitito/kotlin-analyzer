# Extend type-position import code actions to property and return-type annotations

Extend the existing UNRESOLVED_REFERENCE import code-action path to reliably cover type-position annotations in property type declarations and function return types.

## Current state

addTypeImportCodeActions (BridgeCodeActions.kt:586) already fires on UNRESOLVED_REFERENCE diagnostics and calls planTypeImportAssist (BridgeContext.kt:731). planTypeImportAssist checks for KtUserType inside KtTypeReference and for KtNameReferenceExpression outside type references. The KtUserType path (lines 743-761) already handles simple type annotations.

## What's needed

Verify and extend coverage for these specific positions:
- Property type annotations: val x: UserService = ...
- Function return type annotations: fun foo(): UserService { ... }
- Constructor call arguments typed by annotation: val x: List<UserService> = ...
- Nullable type annotations: val x: UserService? = ...

For each position, ensure:
- The unresolved short name is correctly extracted.
- findImportCandidates returns valid candidates from project + classpath symbols.
- Single-candidate case shows "Import 'ShortName'" title.
- Multi-candidate case shows "Import 'ShortName' from fqn" per candidate.
- Same-package and already-imported symbols are filtered out (handled by buildImportEdit).

## Out of scope

- Automatic post-edit import insertion (separate ticket).
- Parameter type annotations (defer until property + return type flows are solid).
- Import insertion for types generated by ka-pg9l explicit type actions.

## Code areas

- BridgeContext.kt: planTypeImportAssist (line 731), findImportCandidates
- BridgeCodeActions.kt: addTypeImportCodeActions (line 586)
- Sidecar integration tests

## Acceptance criteria

- Code action "Import 'X'" appears when cursor is on an unresolved type in a property type annotation.
- Code action "Import 'X'" appears when cursor is on an unresolved type in a function return type annotation.
- Ambiguous matches show one code action per candidate with "Import 'X' from fqn" title.
- Same-package and already-imported types produce no import action.
- Nullable types and generic type arguments are handled.
- Sidecar integration tests cover each position.
