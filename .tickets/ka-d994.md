## Dependencies on BridgeContext

### BridgeCallHierarchy.kt
- `session` -- to get current analysis session
- `findKtFile(session, uri)` -- to locate KtFile from URI
- `lineColToOffset(ktFile, line, character)` -- offset computation
- `analyze(ktFile) { ... }` -- this is `org.jetbrains.kotlin.analysis.api.analyze`, imported directly (not a BridgeContext method)
- `modulesWithFiles` -- accessed via `session.modulesWithFiles` to iterate all project files

### BridgeTypeHierarchy.kt
- `session` -- to get current analysis session
- `findKtFile(session, uri)` -- to locate KtFile from URI
- `lineColToOffset(ktFile, line, character)` -- offset computation
- `analyze(ktFile) { ... }` -- Analysis API function (direct import)
- Analysis API symbols: `KaNamedClassSymbol`, `KaNamedSymbol`, `KaClassType`, `KaClassKind`, `KaTypeRendererForSource`, `Variance`

### BridgePebble.kt
- `pebbleDocuments` -- PebbleDocumentStore for tracking open pebble files
- `pebbleIndex` -- PebbleTemplateIndex for definition/reference lookups
- `pebbleSpringIndex` -- PebbleSpringIndex for Kotlin-Pebble cross-references
- `pebbleSpringIndexDirty` -- dirty flag for lazy rebuild
- `ensurePebbleSpringIndexCurrent()` -- ensures index is rebuilt before queries

### BridgeSymbols.kt
- `symbolIndex` -- SymbolIndex for workspace symbol search

## Notes

- `buildCallHierarchyItem` and `buildTypeHierarchyItem` become private top-level functions in their respective files (not extension functions on BridgeContext) since they only need PSI parameters, not bridge state.
- `ensurePebbleSpringIndexCurrent()` stays on BridgeContext because it is also called by BridgeNavigation's definition path and BridgeCodeActions (line 1304).
- The `analyze(ktFile) { ... }` call in `callHierarchyIncoming` and `typeHierarchySupertypes` is `org.jetbrains.kotlin.analysis.api.analyze` -- a direct import, not a BridgeContext method.
- Total lines removed from CompilerBridge.kt: ~465 (replaced by ~9 one-line facade delegations).
