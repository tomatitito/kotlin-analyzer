# Implement prefix-aware ranking pipeline for non-member Kotlin scope completion

Non-member Kotlin scope completion currently enumerates the full Analysis API scope with little or no prefix filtering or ranking, which buries useful default-imported stdlib top-level functions such as listOf and mapOf. Implement a dedicated matching/ranking pipeline in the sidecar completion path for non-member scope completion only. The initial policy should be exact/prefix-oriented, but the design should leave room for a later fuzzy-match bucket without reworking candidate collection or source-priority rules.

Scope:
- Apply to non-member/scope completion only.
- Keep member completion unchanged unless evidence appears that it shares the same failure mode.
- Preserve unimported symbol suggestions after already-visible in-scope symbols.
- Keep this ticket focused on the initial exact/prefix-oriented policy; fuzzy matching is a follow-up.

Current findings:
- Completion flows through collectScopeCompletions() and uses scopeContext(...).compositeScope { true }.
- The current path emits visible callables/classifiers without meaningful prefix filtering or scoring.
- Keyword completions are appended unconditionally.
- Default-imported stdlib callables such as listOf/mapOf can be present but buried in noisy results.

Implementation direction:
- Keep the fix in sidecar completion generation.
- Separate completion into stages: candidate collection, candidate classification, match/scoring, and final ordering.
- Introduce a candidate model that is independent of Analysis API internals at the scoring stage and carries at least label plus source category (for example: visible in-scope symbol, keyword, auto-import candidate).
- Extract the user prefix before scoring and apply the initial exact/prefix-oriented policy in the matcher/scorer stage.
- Define deterministic score buckets and tie-breakers so tests remain stable. For the initial policy: exact match first, then case-insensitive prefix matches, then remaining visible in-scope symbols, then keywords, with auto-import candidates preserved after already-visible in-scope symbols.
- Treat empty-prefix completion as broad completion: keep visible in-scope symbols available, but still route through the same ranking pipeline so later fuzzy matching can reuse it.
- Do not implement fuzzy matching in this ticket, but structure the scoring stage so a later fuzzy bucket can be added without changing candidate collection or visible-symbol versus keyword versus auto-import ordering rules.

Suggested validation:
- Add integration coverage for prefixes like li and ma and assert listOf/mapOf surface within a deterministic top slice of the visible in-scope results and ahead of keywords.
- Add coverage for empty-prefix completion so the new pipeline does not accidentally suppress normal scope results.
- Preserve existing scope completion and auto-import behavior.

## Acceptance Criteria

- Non-member scope completion runs through a dedicated candidate matching/ranking pipeline before returning items.
- The matcher/scorer stage is structured so a future fuzzy-match bucket can be added without changing candidate collection or source-priority policy.
- Exact and prefix matches for default-imported stdlib top-level functions such as listOf and mapOf surface within a deterministic top slice of visible in-scope results instead of being buried in unrelated noise.
- Member completion behavior is unchanged.
- Keywords remain below already-visible in-scope symbols for non-member scope completion.
- Existing unimported-symbol completion still works and remains ordered after already-visible in-scope results.
- Empty-prefix non-member scope completion still returns normal visible scope results.
- Regression tests cover stdlib top-level completion ranking for non-member scope completion and the ordering boundary between visible symbols, keywords, and auto-import candidates.
