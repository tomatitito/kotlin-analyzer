# Add completion-burst sensor (sensors metrics run completion-burst)

The completion-latency sensor measures isolated single-completion timing inside the sidecar. It does not capture how Zed's typing-burst behavior interacts with the bridge queue, so it cannot validate the latest-wins fix from ka-rr3u or detect regressions in supersession behavior.

Add a 'completion-burst' sensor that drives the real Rust LSP server end-to-end (LSP -> bridge -> sidecar) with configurable bursts and reports the user-visible metrics that matter for typing latency. An ad-hoc Python driver was used during ka-rr3u validation to confirm a ~10-14x improvement on latest-completion latency. That driver was not committed; this ticket promotes the idea into a first-class sensor with its own output rendering.

Implementation
- Lives under tools/sensors/ (new directory).
- Python implementation, primarily so visualization (matplotlib / plotly) is cheap.
- Drives the real kotlin-analyzer LSP binary over stdin/stdout (initialize, didOpen, rapid textDocument/completion bursts), the same path Zed uses.
- Invokable via 'sensors metrics run completion-burst' once the top-level CLI exists; until then, run via 'python3 tools/sensors/completion-burst/main.py' or a thin Cargo/Gradle shim.

Configuration
- project root, target file/line/char
- burst_size (N), burst_count (M)
- inter-request gap (e.g. 5ms / 25ms / 70ms scenarios)
- inter-burst gap (so each burst is measured independently)
- warmup_count (discarded bursts before measurement starts)

Output (sensor-specific rendering, not the generic completion-latency table)
- Per-burst: list of request latencies, latest-only latency, supersession breakdown.
- Aggregate: min/avg/p95/max for latest-only latency across measured bursts; supersession totals (BeforeSend, InFlight); sidecar_queue_wait distribution; sidecar compute distribution.
- Visualization: at least one chart that makes the typing-burst story obvious (e.g. timeline showing N concurrent requests with the superseded ones marked vs. the surviving latest one). Exact chart shape TBD during implementation.
- JSONL raw output for before/after CI comparison.

Operating modes
- Default: pure metrics collector. Reports numbers, never fails.
- Tight-burst regression guard (built into the default scenario set): runs at least one scenario with a small inter-request gap and asserts superseded_before_send + superseded_in_flight == burst_size - 1. Exit non-zero on violation. Catches silent breakage of latest-wins (e.g. someone refactors request_with_supersession and uses the wrong bucket key, so supersession quietly stops working but no test fails).
